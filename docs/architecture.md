# Architecture

WFHub has a SwiftUI iOS app, a Kotlin (Jetpack Compose) Android app, a Rust core they share, a plain HTML/CSS website and a Rust API whose output is static. The site and the API are one Cloudflare Worker deployment served from `https://wfhub.cagatayldzz.com/` (the API under `/api/`, images from `apps/wfhub-web/public`). `scripts/build-site.sh` merges `apps/wfhub-web` and `apps/wfhub-api/data` into `dist/site`, which Cloudflare serves.

## Website and API

`apps/wfhub-web` is the static website (home, legal pages, Swagger page). `apps/wfhub-api` is the Rust API and owns its static data in `data/` (events, mastery, catalogue): a tool that makes the Codex catalogue files, and a Cloudflare Worker (Rust, WASM) that is compiled with `npm run api:build` and committed (`worker/dist`), and mostly serves those files and stores feedback. See the [API README](../apps/wfhub-api/README.md) for configuration and data provenance.

## Shared core

`crates/wfhub-core` is Rust and is used from Swift and Kotlin through UniFFI (see its [README](../crates/README.md)). The apps do the HTTP requests, draw the screens and keep the preferences; the core decides which address to call, reads the JSON answers into view models (`HomeState`, `ActivityPage`, `CodexItem`, `MarketRows`, ...), and owns the translations, countdowns and feedback validation. The bindings are generated by `scripts/build-core.sh` and not committed.

## iOS client

`apps/wfhub-ios/WFHub/WFHubApp.swift` creates the SwiftUI tab view. `Screens/` contains the main views, `Components/` contains shared detail views and visual components, and `Core/` contains shared services (localization is a thin layer over the Rust core). Home, Market, Cycles and Feedback read their data through the core; the activity and Codex detail screens still read raw JSON in Swift. Localized strings are in language-specific `.lproj` directories under `Resources/` and are also embedded in the core.

`project.yml` is the source for the generated Xcode project.

## Android client

`apps/wfhub-android` is a Gradle project (Kotlin, Jetpack Compose, Material 3, Navigation Compose, Coil). Package `com.wfhub.cagatayldzz`: `data/` has the HTTP transport, the preferences and the `load` helper (60 second refresh like the iOS screens), `ui/` has the theme, shared components and navigation, and `ui/screens/` has one file per screen (Home, Activities, Cycles, Market, Codex, Settings, Feedback). Every screen asks the core for its view model and only draws it. The Mastery Rank checklist and ads of the iOS app are not in the Android app yet.
